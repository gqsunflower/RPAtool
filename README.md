# 疑似ローカルAI (RPA特化・Python)

外部のLLM/クラウドAPIを一切使わず、**キーワード/正規表現による意図判定 → 登録済みマクロ実行**
という仕組みだけで「AIっぽく」自然文の指示を処理するRPAツールです。

対応領域は7つです。

- **Excel** (`openpyxl`): 読み込み・シート抽出・CSV変換・セル書き込み・別名保存に加え、
  `.xlsx` だけでなく `.xlsm`(マクロ有効ブック)にも対応しています。RPAでよく使う
  セル・シート操作として、セル1つの値の読み込み・最終行の取得・セルのコピー&貼り付け・
  シートのコピー・シート名一覧の取得・印刷範囲の指定にも対応しています。
  さらに、**複数のExcelファイルを同時に開いたまま、行き来しながら操作できます**
  (`load_workbook` に別名(エイリアス)を付けて複数保持し、`switch_workbook` で
  アクティブなブックを切り替える方式)。
  加えて、openpyxlでは実現できない次の2つは、実際のExcelアプリケーションをCOM経由で
  操作して実現します(**Windows + Excelインストール環境専用、要pywin32**):
  - あらかじめ設定済みの印刷範囲・ページ設定のままPDFとして書き出す
  - `.xlsm` に既に組み込まれているVBAマクロを実行する

  そのほか、RPAで定型的に使う表操作として、**値でセルを検索する**(`find_cell`。
  一致した最初のセルのアドレスを返す)、**表の末尾に1行追記する**(`append_row`。
  最終行の次の行に自動で書き込む)、**行の挿入・削除**(`insert_rows`/`delete_rows`)、
  **セル範囲を空にする**(`clear_range`)、**シートの削除**(`delete_sheet`。ブック内で
  唯一のシートは削除できません)にも対応しています。

  **最終列の取得**(`get_last_column`)にも対応しています。`get_last_row`の列方向版で、
  行番号を指定するとその行で値が入っている最後の列を列文字("A","B",...)で返します
  (省略時はシート全体の最終列)。行に値が1つも無い場合は「A列より前」を表す空文字列を
  返し、`{{変数名+1}}`とすれば正しく"A"が得られます。

  **セルに書き込む・セルをコピーして貼り付ける操作は、「最終行/最終列の続き」を
  基準に貼り付け先を指定できます**(レコーダーの「セル参照の指定方法」/
  「貼り付け先の指定方法」で選択)。列(または行)だけを指定すれば、内部で
  `get_last_row`/`get_last_column`を自動的に1手順追加し、`{{last_row+1}}`のような
  テンプレートを組み立ててくれるため、毎回手動で最終行を取得してからセル参照を
  組み立てる必要がありません。実行のたびに最新の最終行/最終列を再取得するため、
  同じマクロを繰り返し実行すればそのたびに続きへ追記されます。
- **PDF** (`pdfplumber` / `pypdf`): テキスト抽出・複数PDF結合・分割・回転に対応。
  さらにOCR(スキャンPDFからのテキスト抽出)にも対応しています
  (要 `pytesseract` / `pdf2image` と、OS側のTesseract OCR・Poppler)。
  **範囲を指定してのテキスト取得**にも対応しており、ページ左上を基準点(0,0)として、
  幅・高さに対する割合(0〜100%)でx_left/x_right/y_upper/y_lowerを指定した矩形内の
  文字だけを取得できます(OCRにも対応)。改行は文字列 `"ж"` に置換され、1行の
  長い文字列として取得されます。ページの切り出しも「何ページから何ページを1ファイルに」
  「全ページを1ページずつ、または指定ページ数ごとに」の両方に対応し、出力ファイル名の
  ルール(例: `invoice_{page:03d}`)も指定できます。
  そのほか、**ページ数の取得**(`get_page_count`)、**罫線のある表をCSVとして抽出する**
  (`extract_tables`。1ページに複数の表がある場合や複数ページにまたがる場合は空行で区切って
  1つのCSVにまとめます。罫線の無い表は検出できないことがあります)、**埋め込み画像の抽出**
  (`extract_images`。写真・署名画像等をファイルとして書き出す。追加の依存関係は不要)にも
  対応しています。
- **Webブラウザ** (`selenium`): 既定では**Chrome**を操作しますが、`main.py`/`gui_recorder.py`に
  `--browser edge`を付けると**Microsoft Edge**(Chromiumベース)でも動作します。追加のpip
  パッケージは不要(seleniumが両対応)ですが、Edge本体のインストールは別途必要です。

  **マクロごとに使うブラウザを使い分けられます**(社内の一部業務だけEdge指定、といった
  ケース向け)。マクロを記録した時点で使っていたブラウザ(chrome/edge)がそのマクロ自体に
  自動的に保存され、実行時にはマクロごとにそのブラウザへ自動的に切り替わります
  (`--browser`はあくまで「保存が無いマクロ」や「これから新しく記録するマクロ」の
  既定値)。例えば`python main.py --browser edge`で記録したマクロはEdge指定として保存され、
  以後は`--browser`を付けずに実行しても常にEdgeで動きます。同じセッション内でChrome用の
  マクロとEdge用のマクロを混在させて実行することもでき、両方のブラウザが必要に応じて
  開いたまま使い分けられます(パイプライン実行・ステップ実行・ヘルスチェックも対応)。

  ネットには接続しますが、**検索や自由なURL遷移は一切行いません**。
  `config/whitelist_urls.json` に登録したサイトを開く/ログインする/登録済みの操作(クリック・入力・
  選択・待機・画面のPDF保存)を行う、という登録済み操作しか実行できない設計です。
  ボタン等はCSSセレクタやclass名でガチガチに指定せず、**画面に表示されているであろう文字**を
  手がかりに探す「緩い」一致方式(`click_by_text` 等)を基本にしているため、多少のUI変更(見た目の
  微修正等)では壊れにくくなっています。表示テキストでうまく拾えない場合は、F12の開発者ツールで
  調べたCSSセレクタを直接指定する方法にも対応しています。入力欄への入力後にEnterキーで
  送信することもできます。**複数のサイトを別タブで同時に開いたまま、タブを行き来しながら
  操作できます**(`open_registered_site` に `tab_alias` を指定して新規タブを開き、
  `switch_to_tab` で切り替え。ドメインの安全チェックもタブごとに独立して働きます)。
  そのほか、**画面から値を読み取る**(`get_text_by_selector`/`get_attribute_by_selector`。
  CSSセレクタで指定した要素の表示文字や属性値(href等)を取得し、store_asで変数に保存できる)、
  **一覧・表の1列を丸ごと読み取る**(`get_text_list_by_selector`。一致するすべての要素の文字を
  リストとして取得し、for繰り返し構文と組み合わせられる)、**チェックボックスのON/OFF**
  (`check_checkbox_by_text`。ラベルの表示文字を手がかりに探す)にも対応しています。
  チェックボックスは、本体の`<input>`を`opacity:0`等で見た目上隠し`::before`等の疑似要素で
  描画するカスタムデザイン(よくあるスタイル付きチェックボックス)にも対応しています
  (紐づく`<label>`への通常クリックを試し、それでも状態が変わらない場合はJavaScriptで
  input側に直接`.click()`を発火させるフォールバックがあるため、座標や見た目のサイズに
  依存しません)。

  **ウィンドウサイズ・位置・表示倍率の指定**(`set_window_size`/`set_window_position`/
  `set_zoom`)にも対応しています。表示テキストでの操作(`click_by_text`等)ではUI変更に強い
  DOM操作で足りますが、どうしても後述のpyautogui(画面座標クリック)を併用せざるを得ない
  場面に備えて、ウィンドウのサイズ・位置・表示倍率を固定できるようにしてあります。
  - `set_window_size`: `width`/`height`をピクセルで指定するか、`width_percent`/
    `height_percent`で画面全体(モニタの解像度)に対する割合(0〜100%)で指定できる
    (割合指定が優先される)。
  - `set_window_position`: 基準点は画面の**左上(0,0)**、右方向がx増加・下方向がy増加。
  - `set_zoom`: ページの表示倍率(100=等倍)。CSSの`zoom`で実現しているため、別ページに
    遷移すると設定はリセットされる(維持したい場合は遷移のたびに再度呼び出すこと)。

  **注意(Windowsのディスプレイ拡大率について)**: `set_window_size`の割合指定は
  `window.screen`(ブラウザ側のJS)から取得した解像度を基準にしますが、Windowsの
  ディスプレイ拡大率(125%等、既定以外の設定)が有効な環境では、これは
  pyautoguiが認識する実ピクセル数(物理ピクセル)とは**異なる値**になります
  (例: 拡大率125%の環境では、物理1920x1200に対しブラウザ側は1536x960と報告される)。
  pyautoguiの座標・領域指定と厳密に一致させたい場合は、割合ではなく、
  pyautoguiが返す解像度(デスクトップ操作の`get_screen_size`)を基準にピクセル値で
  指定するか、Windows側のディスプレイ拡大率を100%にしておくことを推奨します。
- **エクスプローラー**(標準ライブラリのみ): 指定パスを開く・新規フォルダ作成・ファイル/フォルダの
  移動・コピー・名前変更に対応しています。移動・コピー・名前変更の先に同名のものが
  既にある場合は、明示的に許可しない限り上書きしません(誤ってデータを消さないための
  安全策)。そのほか、**パスの存在確認**(`path_exists`。if_goto等の分岐に使う)、
  **フォルダ内のファイル一覧取得**(`list_files_in_folder`。ワイルドカード指定可)、
  **ファイル/フォルダの削除**(`delete_file`/`delete_folder`。ゴミ箱には移動せず元に戻せない
  ため、レコーダーでは実行前にもう一段階の確認が入ります。フォルダは既定では空の場合のみ
  削除でき、中身ごと削除したい場合のみ明示的に recursive=true を指定します)にも対応しています。
- **実行ファイル(exe/py)**: 自分で作成したPythonスクリプトや実行ファイルを実行できます。
  `config/exec_whitelist.json` に事前登録したファイルのみ実行できる仕組みで、これは
  Webのサイトホワイトリストと同じ考え方です(意図しないファイルが実行されるのを防ぐ)。
  終了コードが0以外の場合は失敗として扱われ、既存のリトライ・失敗時メニューと連携します。
- **デスクトップ**(`pyautogui`): ブラウザのDOMではなく、実際の画面(どのアプリケーションでも)
  を対象に、**画面上の画像を探してクリック・マウス移動**ができます。あらかじめ用意した
  ボタン/アイコンの画像を検索し、見つかった位置をクリックする仕組みです(要
  `pyautogui`。あいまい一致には `opencv-python` も必要)。座標を直接指定するクリックや、
  キーボード入力・特殊キー送信(Ctrl+S等)にも対応しています。画面上のどこでもクリック
  できてしまうため、Webのサイトホワイトリストのような対象制限は原理的に効かせられません。
  そのぶん、実行前には必ず「本当に実行してよいか」の確認が入ります。

  画像検索は**画面全体を対象にする**か、**特定の矩形領域だけに絞る**かを切り替えられます
  (`locate_and_click`/`move_to_image`/`wait_for_image`/`take_screenshot`の`region`引数。
  `(left, top, width, height)`をピクセルで指定。省略時は画面全体)。似たような画像が
  画面の他の場所にもあって誤検出しやすい場合や、検索範囲を絞って高速化したい場合に使う。
  領域の座標を決める基準として、画面解像度を取得する`get_screen_size`もあります。

  **ウィンドウのサイズ・位置指定・アクティブ化**(`set_window_size_by_title`/
  `set_window_position_by_title`/`activate_window_by_title`。要`pygetwindow`)にも
  対応しています。ブラウザだけはSeleniumの機能(前述の`browser.set_window_size`等)で
  同じことがより確実にできますが、**Excel・PDFビューア・エクスプローラー等、Selenium
  で制御できないアプリケーションのウィンドウ**はこちらを使います。タイトルバーの文字列
  (部分一致)を目印にどのウィンドウでも操作できるため、開いているウィンドウのタイトル
  一覧を確認する`list_window_titles`もあわせて用意しています。pyautoguiのクリック・
  キー入力は常に「今アクティブな(最前面の)ウィンドウ」に対して行われるため、複数の
  アプリケーションを行き来しながら操作したい場合は、対象を切り替えるたびに
  `activate_window_by_title`を呼んでおく必要があります。
- **テキスト加工**: Excelのセル・PDFの範囲テキスト・OCR結果などを取得した後の
  文字列加工です。特定の文字を探して(含める/含めないを選んで)そこから文字数指定、
  または別の文字が出るまでを切り出す、文字の置換、文字列の結合・付加に対応しています。

  **日付・時刻の取得**(`format_now`)は、Excelのユーザー定義表示形式に似た書式
  コードで指定します。使えるトークン: `yyyy`(西暦年)/ `YYYY`(年度。開始月は
  `fiscal_year_start_month`で指定、既定4月)/ `MM`・`M`(月、2桁ゼロ埋め/なし)/
  `dd`・`d`(日、同様)/ `hh`・`mm`・`ss`(時・分・秒、2桁ゼロ埋め)。トークン以外の
  文字(区切りの"_"や"年"等)はそのまま残ります。よく使う書式はレコーダーで
  プリセットとして選べます: `yyyyMMdd_hhmmss`(ファイル名の一意化)、`yyyyMMdd`、
  `hhmmss`、`yyyy`、`YYYY`。store_asで変数に保存すれば、Excel・PDF・
  エクスプローラー・Webのどの手順の値欄でも`{{変数名}}`として埋め込んで使えます
  (例: 保存ファイル名を`report_{{now}}.xlsx`にする、Webフォームに日付を入力する等)。

## 前の手順の結果を後の手順で使う(変数・パイプライン)

Excelのセル読み込みやPDFの範囲テキスト取得、最終行の取得など「値を取得する」
手順には、結果を**変数として記録して後の手順で使う**機能があります。手順の
記録時に「この結果に名前を付けて後の手順で使いますか?」と聞かれるので、
名前を付けると、以降のどの手順の入力欄でも `{{その名前}}` と書くだけで
実行時の値がそのまま渡されます。

**値全体をそのまま使う場合**(型を維持):

```
{"end_page": "{{last_row}}"}
```
→ `last_row` が整数42なら `end_page` にはそのまま整数42が渡ります。

**他の文字列の一部として埋め込む場合**(文字列として結合):

```
{"source_range": "A1:B{{last_row}}"}
{"output_path": "report_{{last_row}}.xlsx"}
```
→ `last_row` が152なら、それぞれ `"A1:B152"` `"report_152.xlsx"` になります。
1つの文字列の中に複数の変数を含めることもできます
(例: `"{{this_year}}_{{invoice_no}}.pdf"`)。

**変数に対して簡単な計算をする場合**(加減算):

```
{"dest_cell": "A{{last_row+1}}"}
```
→ `last_row` が152なら `"A153"`(最終行の「次の行」)になります。
`{{変数名+数値}}` / `{{変数名-数値}}` の形で、変数名の後ろに `+` または `-` と
数値を続けて書くと、その場で加減算した値を使えます。「最終行の1つ下に
追記する」「開始行を1つ前にずらす」といった用途に使います
(掛け算・割り算には対応していません)。

変数の値がExcelの列文字("A","B","AA"等)の場合、`+`/`-`は列文字としての
加減算になります(例: `last_col` が"C"なら `{{last_col+1}}` は"D")。
`get_last_column`と組み合わせて「最終列の1つ右に書き込む」際に使います。

セルの書き込み先(`excel.write_cells`の`cell_values`)は、**値だけでなくキー
(セル参照)にも** `{{ }}` を使えます。例えば `{"B{{last_row+1}}": "値"}` は
実行時に `last_row` が10なら `{"B11": "値"}` として書き込まれます
(レコーダーの「セルに書き込む」で「最終行/最終列の続き」を選ぶと、この
書き方が自動的に組み立てられます)。

**具体例**: 「Excelで最終行を取得する(store_as: `last_row`)→ セルをコピーする
際、コピー元の範囲を `A1:B{{last_row}}` と入力し、貼り付け先を
`A{{last_row+1}}`(最終行の次の行)にする → 保存ファイル名を
`report_{{last_row}}.xlsx` にする」という一連の流れが、そのまま1つのマクロとして
組み立てられます。

登録時、値の欄に `{{変数名}}` を(単独でも、他の文字と組み合わせても)直接
入力すると、その場では実行時の値が定まらないため動作確認はスキップされ
(GUIではその旨がログに表示されます、CLIでは代わりに動作確認用の実値を
別途聞かれます)、テンプレートのままマクロに登録されます。

**変数の型と、型を強制的に変換する場合**: Excelのセル値等は郵便番号のような
先頭が0の値を保持するため、基本的に文字列(str)として取得されます。加減算
(`{{変数+1}}`)を行うときはその場でfloatに変換して計算し、計算結果に小数点
以下が無ければintで返す、という扱いです(値そのものの保存形式を勝手に
数値化することはありません)。それでも明示的に型を変えたい場合は、制御構文の
「変数の型を変換する」(`to_str`/`to_int`/`to_float`)を使います。

```
{"handler":"control","action":"to_int","params":{"value":"{{count}}"},"store_as":"count"}
```
`count` が文字列"3.0"であれば整数3に変換されます(to_intはfloatを経由するため、
"3.5"のような値は3になります)。逆に数値を確実に文字列として扱いたい場合は
to_strを使います。

**クリップボードとの連携**: テキスト加工の「クリップボードにコピーする」
「クリップボードから取得する」を使うと、取得した値をOSのクリップボードへ
保持して他のアプリへ手動で貼り付けたり、逆に手動でコピーしておいた値を
マクロの入力(変数)として取り込んだりできます(要 `pyperclip`。Linuxでは
さらに `xclip` または `xsel` が必要)。

## 操作の登録方法(レコーダー)

`python main.py` を起動し、指示欄に **「操作を登録」** と入力すると、対話形式で
**Excel・PDF・Webサイト・エクスプローラー・実行ファイル(exe/py)・デスクトップの
操作を自由に組み合わせて**1つの一連の流れとして覚えさせられます。「Excelから読み込む →
PDFを結合する → フォルダへ移動する → 登録済みサイトにアップロードする →
後処理スクリプトを実行する」のような複数領域にまたがる手順も、1回の登録で
まとめて作れます。各手順は実際にその場でファイル/ブラウザ/プロセスに対して
実行して確認してから登録する方式です。

## GUI版レコーダー(ボタン操作・D&D・クリップボード画像貼り付け対応)

cmdでのメニュー番号入力の代わりに、ボタンをクリックする・入力欄に文字を
入れて送信する、という操作で登録したい場合は、指示欄で **「GUIで操作を登録」**
と入力するか、直接次のコマンドを実行してください。

```bash
python gui_recorder.py
```

中身はコマンドライン版と全く同じ土台(同じExcel/PDF/Web/エクスプローラー/
実行ファイル/デスクトップのハンドラ、同じ保存先・自動バックアップ)を
再利用しており、対話部分だけをTkinterのフォーム・ボタンに置き換えています。
そのため、GUIで登録したマクロもコマンドライン版で登録したマクロも全く同じ
`config/macros.json` に保存され、区別なく使えます。

**画面の使い方**: 上部の「領域」「操作」の2つのプルダウンで対象を選ぶと、
その下にフォームが表示されます。値を入力して **「動作確認して登録」** ボタンを
押すと、実際にその場で操作を試したうえで手順として記録されます。記録済みの
手順は画面下部に一覧表示され、間違えたら **「元に戻す」** でいつでも直前の
1手順を取り消せます。最後に **「保存して終了」** で保存名・説明・呼び出し
キーワードを入力すれば完了です。

**ブラウザの切り替え(上部プルダウン)**: 「領域」「操作」の右に「ブラウザ」
プルダウンがあり、Chrome/Edgeをその場で切り替えられます(起動時の`--browser`は
この初期値になるだけで、後からいつでも変更できます)。既にブラウザを起動済み
(サイトを開く操作を1回でも行った)状態で切り替えると、今開いている画面は
閉じられるため確認ダイアログが出ます。切り替え後に登録するマクロは、
保存時にその時点で選ばれているブラウザで記録されます。

**変数一覧パネル(右側)**: store_asで保存した変数・リストは、画面右側に
**変数名(型)と実際に確認できた値**が一覧表示されます。手順を登録するたびに
自動的に更新され、直前の手順を取り消すとその変数も一覧から消えます。あくまで
「記録した時点で動作確認できた値」のスナップショットのため、次回実行時に
Excelの中身が変わっていれば最終行等の値は変わりうる点に注意してください
(CLI版では指示欄で「操作を登録」中に番号を選ぶと同様の一覧を表示できます)。

**ファイル/フォルダをドラッグ&ドロップで入力**: Excel/PDF/フォルダ/exe・py等、
**パスを入力する欄には全て、Windowsのエクスプローラーからファイルやフォルダを
直接ドラッグ&ドロップして入力できます**(「参照...」ボタンが付いている欄が対象)。
複数ファイルをまとめて追加する欄(PDF結合のファイル一覧など)は、複数選択した
ファイルを一度にドロップすればまとめて追加されます。要 `tkinterdnd2`
(`pip install tkinterdnd2`)。インストールされていない場合はD&Dが使えないだけで、
「参照...」ボタンやパスの直接入力は通常どおり使えます。

**クリップボードから画像を貼り付けて登録**(デスクトップ操作向け): 「デスクトップ」
領域の「画像を探してクリックする」を選ぶと、画像パスの入力欄の横に
**「クリップボードから貼り付け」** ボタンがあります。事前にWindowsの
「Win + Shift + S」(切り取り&スケッチ)等でクリックしたいボタン/アイコンを
画面から範囲コピーしておけば、このボタン1つでその画像を直接クリック対象として
使えます(いったんファイルに保存してパスを手入力する手間が要りません)。
画像ファイルそのものをドラッグ&ドロップすることもできます。貼り付けた/
ドロップした画像はその場でプレビュー表示されます。

**注意点**:
- GUIはTkinter(Python標準)で作られていますが、環境によっては
  `python3-tk` 等のOSパッケージの追加インストールが必要な場合があります。
- ドラッグ&ドロップには `tkinterdnd2` が必要です。未インストールの場合、

- クリップボードからの画像取得は、Windows/macOSでは標準機能で動作しますが、

- Web操作を追加する際にサイトを未選択のまま他の操作を開くと、フォームの

**セルのコピー&貼り付けの方式について**: 「値のみ」は数式セルも計算済みの値としてコピーします。「数式」はセル参照(`=SUM(A1:A5)` 等)をそのままコピーしますが、**Excelの通常のコピー貼り付けと違い、貼り付け先に合わせた相対参照の自動調整は行いません**(貼り付け元の数式文字列がそのまま複製されます)。「すべて」は値/数式に加えて、数値の表示形式・フォント・塗りつぶし・罫線・配置もコピーします(列幅/行高・条件付き書式・コメント・入力規則は対象外です)。

サイト内で想定外のドメインに遷移した場合は、クリックや入力のたびに検知して例外を出し停止します。

## ファイル操作・実行ファイルの安全設計

- **上書き保護**: ファイル/フォルダの移動・コピー先に同名のものが既にある場合、
  `overwrite` を明示的に許可しない限りエラーで停止します(意図しないデータ消失の防止)。
- **移動の事前確認**: 移動は元の場所から無くなる操作のため、レコーダーで記録する際、
  実際に試す前にもう一段階「本当に実行してよいか」を確認します。
- **実行ファイルのホワイトリスト**: exe/pyの実行は、Webのサイトホワイトリストと
  同じ考え方で `config/exec_whitelist.json` に事前登録したファイルのみ実行できます。
  スロットの値が想定外の文字列になった場合でも、無関係なファイルが実行されることは
  ありません。
- **shell=Trueは使用しません**: 引数へのシェルインジェクションを避けるため、
  常にリスト形式でプロセスを起動します。
- **終了コードのチェック**: exe/pyが0以外の終了コードで終わった場合は失敗として扱われ、
  既存のリトライ・失敗時3択メニューと連携します。

## デスクトップ操作の安全設計と使い方のコツ

- **対象を制限できない**: Web操作のようなサイトホワイトリストに相当する仕組みは、
  画面操作という性質上作れません(画面上のどこでもクリック・入力できてしまうため)。
  そのぶん、移動やexe/py実行と同様、実行前には必ず「本当に実行してよいか」の
  確認が入ります。
- **画像素材の作り方**: 「6) 今の画面のスクリーンショットを撮る」でデスクトップ全体を
  撮影し、そこから対象ボタン/アイコンの部分だけをペイントソフト等でトリミングして
  別ファイルに保存し、そのパスをクリック操作の登録で指定します。周囲の余白が
  少なすぎたり、似たアイコンが画面内に複数あったりすると誤検出しやすくなるため、
  できるだけ特徴的な範囲を切り出すことをおすすめします。
- **confidence(一致の緩さ)**: 既定値は0.8。低くしすぎると誤った場所をクリックする
  恐れがあるため、必要な範囲で調整してください。`opencv-python` が無い環境では
  この指定は無視され、常に完全一致でのみ検索します。
- **座標クリックは最終手段**: `click_at` は画面解像度やウィンドウの配置に強く依存し、
  別のPCや解像度変更後には位置がずれる可能性があります。可能な限り画像検索
  (`locate_and_click`)を優先してください。
- **緊急停止**: pyautoguiのFAILSAFE機能を有効にしているため、実行中にマウスカーソルを
  画面の左上隅(座標(0,0))へ動かすと例外が発生してすぐに止められます。

## 手順の並び替え・削除・挿入(手順編集)

登録したマクロの手順を後から編集したい場合は、指示欄に **「手順編集」** と
入力します。マクロを選ぶと、各手順が番号付きで一覧表示され、次の操作ができます。

- **上へ移動する / 下へ移動する**: 選んだ手順を前後に1つずつ動かします
- **削除する**: 選んだ手順だけをピンポイントで削除します(確認あり)
- **指定した位置の前に新しい手順を挿入する**: 挿入したい位置(何番目の手順の
  前か)を指定してから、通常の「操作を登録」と同じ領域選択・フォームで
  新しい手順を1つ以上追加できます。挿入時は、その位置までに実行されている
  はずの状態(直前に開かれていたWebサイト、直前に読み込まれていたExcel
  ブック)をベストエフォートで再現してから追加作業に入ります
  (ファイルパスが変数({{ }})を含む場合など、値が分からず再現できない
  ケースもあります。その場合は手動で該当操作を先に済ませてから追加してください)。

制御構文(ラベル・for)を含むマクロで並び替え・削除を行うと、ラベルの対応や
for の対応関係が崩れる場合があります。操作の直後に簡易チェックが走り、
問題があれば警告が表示されます(自動修正はしないため、内容を見て手動で
直してください)。

## 既に登録済みのマクロ同士を繋げる(パイプライン)

レコーダーでは1回の登録セッション内でExcel・PDF・Webを自由に組み合わせられますが、
**すでに個別に登録した複数のマクロ**(例:Excel転記マクロ、PDF結合マクロ、
Webアップロードマクロをそれぞれ別々に作ってあった場合)を、後からまとめて
連続実行したいこともあります。その場合は「複数マクロの連続実行(パイプライン)」
の節で説明している **「パイプライン作成」** / **「パイプライン実行」** を使ってください。
考え方の違いは次のとおりです。

- **操作を登録**: 1つのマクロの「中身」としてExcel・PDF・Webの手順を自由に混在させる
- **パイプライン作成**: 既に別々に存在するマクロを、実行する「順番」でつなげる

## 操作を間違えたときの取り消し方

登録中に操作を間違えることは当然あるので、2段階で取り消せるようにしています。

**① 目印/パスを入力する時点でキャンセルする**

クリック/入力/ドロップダウンの目印(表示文字やラベル)や、Excel/PDFの
ファイルパス・シート名などを聞かれた際に、「**キャンセル**」(または
`cancel` / 戻る / やめる)と入力すると、その操作は一切記録せずに
メニューへ戻ります。まだ実行前・記録前の段階なので何も影響を残しません。

```
  押したいボタン/リンクに表示されている文字を入力してください(間違えた場合は「キャンセル」): キャンセル
  → この操作の記録をキャンセルしました。メニューに戻ります。
```

**② 記録してしまった直前の操作を取り消す**

すでに記録・登録してしまった操作(Excel/PDF/Web/エクスプローラー/実行ファイル/
デスクトップいずれも)を間違えた場合は、メインメニューで
**「9) 直前の操作を取り消す」** を選びます。直前の1手順が削除され、
その手順でしか使っていなかったスロット(`{{order_no}}` など)があれば
一緒に取り除かれます。何度でも連続して選べば、その分だけ前に戻れます
(まだ何も記録していない状態より前には戻れません)。Webサイトを開く手順を
取り消した場合は、次にWeb操作を追加するときに改めてサイト選択からやり直します。

```
次はどの操作を追加しますか?
番号> 9
  → 直前の操作を取り消しました: browser.click_by_text {'text_hint': '送信'}
  現在、記録済みの操作は 2 件です。
```

## 操作後の成功確認と、確認の省略設定

「ボタンを押したつもりが実は押せていなかった」まま処理が先へ進むと、意図しない
操作を連鎖させてしまう危険があります。これを防ぐため、クリック・入力・選択の各手順には
**実行直後に確認する仕組み**を組み込めます。

登録(レコーダー)時、各手順のあとに次のように聞かれます。

```
  この操作が『本当に成功したか』をどう確認しますか?
    1) この後、特定の文字が新しく表示されるはず
    2) この後、画面のURLが変わるはず
    3) 確認しない(ほぼ失敗しない操作の場合。後から個別に変更も可能)
```

- **1) 特定の文字が表示される**: 例えば「保存」を押した後に「保存しました」という文言が
  出るサイトなら、その文言を登録しておくと、実行時に本当に表示されたかを確認します。
- **2) URLが変わる**: 画面遷移を伴う操作(次のページへ進む等)に向いています。
- **3) 確認しない**: 常に失敗せず、確認しようがない操作(単なる待機など)向けです。

実行時にこの確認が取れなかった場合、**そのマクロの残りの手順は一切実行されず、
その場でエラーとして停止します**。誤った状態のまま次の操作(送信・削除など)に
進んでしまうことを防ぎます。

### 確認を後から省略する

一度「確認あり」で登録した手順でも、実際に使ってみてほぼ失敗しないとわかった場合は、
指示欄に **「確認設定」** と入力すると、マクロ・手順を選んで確認の有無をその場で
切り替えられます(確認の設定内容自体は消えないので、いつでも元に戻せます)。

```
指示> 確認設定
確認動作を設定するマクロを選んでください:
  1. order_submit
  ...
番号> 1

『order_submit』の手順:
  1. browser.click_by_text — 確認あり (text_appears)
  2. browser.type_by_text — 確認あり (text_appears)
番号を入力するとその手順の確認の有無を切り替えます。0で戻ります。
番号> 1
  → この手順は今後『省略する』ようになりました
```

`config/macros.json` を直接編集し、各ステップに `"verify_skip": true` を
設定することでも同じことができます。

## 失敗時にどうするか(即時終了・手動補完して再開・修正画面を開いて終了)

自動化した操作が途中で失敗した(ボタンが実は押せていなかった、確認が取れなかった等)まま
先に進むと、意図しない操作の連鎖につながる危険があります。そのため、いずれかの手順が
失敗すると、その場で処理を止めて次の3択が表示されます。

```
⚠ ステップ 3/5 (browser.click_by_text) が失敗しました:
   '送信' という表示のボタン/リンクが見つかりませんでした
  どうしますか?
    1) 今すぐ中断する
    2) この操作を手動で終わらせてから、続きを再開する
    3) 中断して、この手順の修正画面を開く
  番号>
```

- **1) 今すぐ中断する**: そこで処理を止めます(以降の手順は一切実行しません)。
- **2) 手動で終わらせてから続きを再開する**: 開いたままのブラウザで自分の手で
  操作を終わらせ、Enterキーを押すとその手順は「手動完了」として扱われ、
  **次の手順から**自動実行を再開します。
- **3) 中断して修正画面を開く**: その手順のパラメータ(ボタンの表示文字など)を
  その場で対話的に修正して保存できます。保存後、プログラムは終了します
  (可能であればOS標準のエディタでも `macros.json` を開きます)。

## ステップ実行(EXCELマクロのF8相当)・途中から開始する動作確認

指示欄に **「ステップ実行」** と入力すると、対象マクロを選んだうえで
1手順ずつ実行しながら結果を確認できます。

```
指示> ステップ実行
対象のマクロを選んでください:
  1. order_submit
番号> 1
『order_submit』は全4ステップです。
何番目のステップから開始しますか?(先頭からなら1。1〜4): 1

--- ステップ 1/4: browser.open_registered_site ---
  params: {'site_key': 'example_portal'}
  [Enter] 1ステップだけ実行して次で止まる(F8相当)   [c] 続きを自動実行   [s] このステップをスキップ   [a] 中断
  > (Enter)
  実行結果: https://example.com/portal/login

--- ステップ 2/4: browser.click_by_text ---
  ...
```

- **Enter**: そのステップだけ実行し、また次のステップの前で止まります(F8相当)。
- **c**: そこから先は止めずに最後まで自動実行します。
- **s**: そのステップを実行せず読み飛ばします。
- **a**: そこで中断します。
- 開始時に「何番目のステップから開始しますか?」と聞かれるので、
  途中まで手動で準備した状態から続きだけ自動化する、といった使い方もできます
  (その場合、それより前のステップ(サイトを開く等)は実行されないため、
  ブラウザなどの状態は事前に手動で用意しておく必要があります)。
- ステップ実行中も、失敗時には上記と同じ3択メニューが表示されます。

## 一時的な失敗に対する自動リトライ

ネットワークの遅延やページの読み込み待ちなど「少し待てば成功する」類の失敗まで
毎回3択メニューを出すのは煩雑です。登録(レコーダー)時、確認方法のあとに

```
読み込み待ちなどで失敗しやすい操作ですか? 自動で再試行する回数を入力してください(不要ならそのままEnter):
```

と聞かれるので、回数を入れておくとその手順だけ、失敗時にまず自動で
指定回数だけ再試行してから(3択メニューを出す前に)判定します。
`config/macros.json` のステップに `"retry": {"count": 2, "interval_seconds": 3}`
のように直接書いて調整することもできます。

## 失敗時の自動スクリーンショット保存

リトライを使い切ってもなお失敗した場合、その瞬間のブラウザ画面が自動的に
`logs/screenshots/` にPNGで保存されます(ファイル名にマクロ名・ステップ番号・
日時が入ります)。あとから原因を調べるときの手がかりになります。

## 実行ログの記録とExcel出力

すべてのステップの実行結果(成功/失敗/スキップ/手動補完)は自動的に
`logs/execution_log.csv` に記録されます。指示欄に **「実行ログ出力」** と
入力すると、その時点までの記録を `logs/execution_log_YYYYMMDD_HHMMSS.xlsx`
としてExcel形式で書き出せます。業務の実施記録や、不具合が起きたときの
調査に使えます。

## マクロ変更の自動バックアップ

`config/macros.json` や `config/pipelines.json` を書き換える操作
(操作の登録・確認設定の切り替え・修正画面での保存・パイプラインの保存)を行うと、
その直前の内容が自動的に `config/backups/` にタイムスタンプ付きで
コピーされます(直近30世代を保持し、古いものは自動的に整理されます)。
誤って登録内容を壊してしまった場合は、該当のバックアップファイルを
`config/macros.json` として上書きコピーするだけで元に戻せます。

## 複数マクロの連続実行(パイプライン)

「Excelから転記 → PDFを結合 → 登録済みサイトにアップロード」のような
一連の定型業務をまとめて実行したい場合は、指示欄に **「パイプライン作成」**
と入力し、含めるマクロを実行したい順番で選んで名前を付けます。

```
指示> パイプライン作成
パイプラインに含めるマクロを、実行したい順番でカンマ区切りの番号で選んでください:
  1. excel_extract_to_csv
  2. pdf_merge
  3. web_registered_login_download
番号(例: 1,3,2)> 1,2,3
このパイプラインの保存名(半角英数字)を入力してください: monthly_report
説明を一言でお願いします: 月次レポート作成の一連の流れ
  → パイプライン 'monthly_report' を保存しました (excel_extract_to_csv → pdf_merge → web_registered_login_download)
```

実行するときは **「パイプライン実行」** と入力し、対象を選ぶだけです。
各マクロに必要なスロットはそのマクロの実行直前に確認されます。途中の
マクロが失敗した場合は、そこでも失敗時の3択メニュー(即時終了/手動補完して
再開/修正画面を開く)が表示され、パイプライン全体もその判断に従います。

## ヘルスチェック(登録済みボタン等が今も見つかるかの事前確認)

相手サイトのUI変更を、実際の業務で使う前に検知したい場合は、指示欄に
**「ヘルスチェック」** と入力します。登録済みの `click_by_text` /
`type_by_text` / `select_by_text` の目印が、実際にはクリック・入力せずに
今のサイト上で見つかるかどうかだけを確認して一覧表示します。

```
指示> ヘルスチェック
ヘルスチェックの対象を選んでください:
  0. すべてのマクロ
  1. order_submit
番号> 0

■ order_submit
  ✅ open_registered_site {'site_key': 'example_portal'}
  ✅ click_by_text {'text_hint': '発注申請'}
  ❌ click_by_text {'text_hint': '送信'} (表示テキストに一致する要素が見つかりません)
```

**制約**: この確認は同一画面内の要素検出に限られます。複数ページに
またがる手順の後半は、実際にクリックして遷移していない都合上、正しく
検証できないことがあります(参考情報としてご利用ください。厳密に
確認したい場合は「ステップ実行」を使ってください)。

### 定期的なヘルスチェック(タスクスケジューラ / cron)

対話なしで全マクロのヘルスチェックだけを行い、問題があれば終了コード1で
終わるモードも用意しています。

```bash

```

Windowsのタスクスケジューラや、Linux/macOSのcronにこのコマンドを
毎朝実行するよう登録しておけば、業務で使う前にUI変更を早期発見できます。

## 仕組み(なぜ「疑似AI」なのか)

```
ユーザーの指示文
   ↓
IntentEngine (engine/intent_engine.py)
   … config/intents.json のキーワード・正規表現とスコアリングし、
     最も一致度の高い「意図(=実行すべきマクロ名)」を選ぶ
   ↓
MacroExecutor (engine/executor.py)
   … config/macros.json に定義された手順(steps)を順番に実行
   ↓
各Handler (handlers/excel_handler.py / pdf_handler.py / browser_handler.py)
   … 実際にExcel/PDF/ブラウザを操作
```

本物の言語モデルは使っていません。すべてルールベースの分類器+事前登録された
操作手順の組み合わせで「指示を理解して動いているように見える」動作を実現しています。

## 外部ツールから1コマンドで実行する(Power Automate Desktop等との連携)

Power Automate Desktopなど、別のツールから作成済みのフロー(pyスクリプト)を
呼び出すような運用がある場合、`--run-macro` を使うと対話なしで指定マクロを
1回だけ実行して終了できます。成功なら終了コード0、失敗なら1を返すので、
呼び出し側で成否を判定できます。

```bash
python main.py --run-macro monthly_report --slots "{\"path\": \"C:\\data\\a.xlsx\"}"
```

- `--run-macro` にはマクロ名(`config/macros.json` に登録済みのもの)を指定します。
- `--slots` は省略可能で、マクロが必要とするスロットをJSON文字列で渡します。
- 無人実行を想定しているため、失敗時は3択メニュー等の対話は行わず、そのまま
  失敗として終了します(手動補完や修正画面は使えません)。事前に「ステップ実行」等で
  十分に動作確認したマクロを登録してから使うことをおすすめします。

他のPythonスクリプトから呼び出したい場合は、`subprocess.run(["python", "main.py",
"--run-macro", "マクロ名"])` のように起動し、戻り値の `returncode` で成否を
確認する形になります。

## 拡張方法

### 1. 新しい意図(指示文パターン)を追加する

`config/intents.json` の `intents` 配列に追記します。`keywords`(部分一致、各+1点)と
`patterns`(正規表現、マッチで+2点)の組み合わせでスコアリングされ、`match_threshold`
以上で最高得点のものが採用されます。

### 2. 新しいマクロ(操作手順)を追加する

`config/macros.json` に `handler`(excel/pdf/browser)と `action`(各Handlerのメソッド名)
の並びを定義します。`params` に `{{slot名}}` と書くと、実行時にユーザー入力で置換されます。

### 3. 新しいブラウザ操作先を追加する

`config/whitelist_urls.json` に `site_key` を追加しない限り、`browser_handler.py` は
そのサイトを一切開けません(`SiteNotWhitelistedError`)。遷移後も登録ドメインと
一致するかを毎回検証し、不一致なら停止します(`NavigationBlockedError`)。

### 4. 新しいHandler(操作対象)を追加する

`handlers/` に新しいクラスを作り、`main.py` の `build_handlers()` に登録すれば、
`macros.json` から `"handler": "新ハンドラ名"` で呼び出せるようになります。

## 安全上の制約(設計方針)

- ブラウザハンドラに「任意URLへ遷移する」actionは存在しません。新しいサイトも
  レコーダー経由で明示的にホワイトリスト登録されない限り開けません。
- 検索エンジンへの問い合わせを行う機能は実装していません。
- 認証情報は環境変数からのみ取得し、設定ファイルやコードに書きません。
- クリック・入力・選択のたびに現在のドメインを検証し、意図しないリダイレクト・
  ホワイトリスト外への誘導を検知した場合は例外を出して処理を停止します。
- 各手順に登録した「確認方法」(表示文字/URL変化)が実行時に取れなかった場合、
  既定ではマクロの残りの手順は実行されず即座に停止します(誤操作の連鎖防止)。
  ただし失敗時メニューで「手動で終わらせて再開」を選んだ場合のみ、その手順を
  手動完了とみなして次の手順から続行します。
- `--dry-run` により、実際にファイルを書き換えたりブラウザを操作したりする前に
  手順を確認できます。「ステップ実行」により1手順ずつ実際に動かしながらの
  確認も可能です。

## 既知の制約

- 表示テキストによる緩い一致は、同じ文言のボタンが画面内に複数ある場合、
  DOM上で先に出現する(かつ完全一致を優先した)ものを操作します。曖昧な場合は
  もう少し具体的な文言(周辺のラベルを含める等)を登録し直してください。
- 現時点ではSPA(単一ページアプリ)の非同期描画完了待ちは `wait_seconds` /
  `wait_for_text` を手動で挟む前提です(自動検知はしていません)。
